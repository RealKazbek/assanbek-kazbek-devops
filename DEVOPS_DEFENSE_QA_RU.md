# Вопросы и ответы к защите

1. **Что делает `pwd`?** Показывает текущий каталог.
2. **Зачем нужен `find`?** Ищет файлы; здесь находит `logs/application.log`.
3. **Что выводит `grep ERROR application.log`?** Все строки лога с `ERROR`.
4. **Как посчитать ошибки?** `grep -c ERROR logs/application.log`; в текущем логе их две.
5. **Что делает `tail -n 5`?** Показывает последние пять строк файла.
6. **Что означают r, w, x?** Read, write и execute.
7. **Что означают права 600?** Владелец читает и пишет; group и others не имеют прав.
8. **Почему public.txt имеет 644?** Владелец может менять файл, остальные могут читать.
9. **Что делает Bash-скрипт проекта?** Печатает персональную и системную информацию и проверяет `Assanbek_Kazbek_info.txt`.
10. **Что такое процесс?** Выполняющаяся программа с ресурсами ОС.
11. **Что такое PID?** Уникальный идентификатор процесса.
12. **Разница между `ps` и `top`?** `ps` — моментальный снимок; `top` — обновляемое представление.
13. **Что такое Git commit?** Зафиксированная версия изменений с SHA и сообщением.
14. **Зачем нужна ветка development?** Для изолированной работы и проверки до merge в main.
15. **Разница между git pull и git push?** Pull получает изменения с remote; push отправляет commits на remote.
16. **Зачем .gitignore?** Чтобы не добавлять логи, backup, `.env`, кэш и возможные секреты.
17. **Что такое Docker image?** Неизменяемый шаблон приложения и окружения.
18. **Что такое Docker container?** Экземпляр image, который можно запускать, останавливать и удалять.
19. **Как приложение получает персональные данные?** Из STUDENT_NAME, STUDENT_SURNAME, STUDENT_GROUP и STUDENT_ID; иначе используются Kazbek Assanbek, IT2-2302, 37765.
20. **Почему переменные окружения полезны?** Меняют конфигурацию без пересборки image.
21. **Почему нельзя хранить секреты в Dockerfile?** Они могут попасть в слои image и историю.
22. **Зачем Docker Compose?** Он декларативно описывает сервис и запускает настройки одной командой.
23. **Какие стадии Jenkinsfile?** Checkout, Build, Test, Docker Build, Docker Run.
24. **Что делает Checkout?** Получает commit исходного кода из GitHub.
25. **Что происходит при ошибке Test?** Pipeline останавливается; Docker Build и Docker Run не выполняются, итог не SUCCESS.
26. **Что такое CI/CD в этом проекте?** Jenkins получает код, проверяет его, строит image и запускает container.
27. **Как проверить container?** `docker ps`, `docker logs assanbek-kazbek-container`, `curl http://localhost:8080/` и `docker exec`.
28. **Какой commit проверен в аудите?** Local/remote main: `98c826604803a57096f2b8a36dd66d7f6d7906f5`.
29. **Какой свежий результат Jenkins?** Build #5 реально получил этот SHA из GitHub и завершился `Finished: SUCCESS`.
